# Правки старшего ментора в чек-листе — дизайн

**Дата:** 2026-09-14
**Статус:** утверждён
**Базовая спека:** [`review-homework.md`](review-homework.md)

## Задача

Старший ментор потока (`rissenberg`, Костя Горшков) заходит в PR только после
лейбла «ОК от ментора» и на всех 17 проверенных PR вернул работу с новыми
замечаниями. Значит черновик скилла не ловит то, что он ловит гарантированно,
и каждый PR делает лишний круг через студента и старшего.

Цель батча: заложить в скилл всё, что он находит повторяемо, чтобы студент
приходил к нему уже с ответами. Источник — 59 инлайн-заметок и 3 общих
комментария в `homework_2026_2` по состоянию на 2026-09-14.

## Исследование

Разобраны все ревью-комментарии репозитория (912 инлайн, 147 общих).
Заметки старшего ментора распадаются на девять повторяющихся тем:

Остальные заметки (`'use strict'`, стрелочная функция, перенос строки,
`!==`, `let`, отступы, CI) чек-лист уже покрывает.

Наблюдения о поведении, которые влияют на дизайн:

- Он **не аппрувит, пока на теоретический вопрос нет ответа** (#6: «а ответ
  так и не написал»).
- Он **принимает аргументированный отказ**: в #17 студент отстоял возврат `{}`
  ссылкой на базовый тест и JSDoc — аппрув без дальнейших правок; в #23
  студент объяснил, почему объект вместо `Map` годится — аппрув.
- Исключение для циклов он проговорил сам (#16): перебор по ключам объекта
  на метод массива не заменяется.

## Решения

| Вопрос | Решение |
|---|---|
| Невалидный вход (B1) | По умолчанию просим `throw new TypeError`. Возврат `null`/пустого значения получает вопрос «почему не ошибка?». Задокументированный в JSDoc и последовательный выбор — не находка |
| Экзотические объекты | Все варианты с объектом на входе: 2, 3, 5, 6, 7, 8, 14, 18. Строка в C0, отсутствие теста — обязательная заметка по C1. Подсказка про `toString.call` — вопросом, не требованием |
| Вопросы сверх задания | Поднимаются в первом ревью ментора как вопросы на понимание. Переделка и аргументированный отказ оба закрывают тред |
| Гейт ответов | «ОК от ментора» не предлагается, пока в тредах ментора есть теоретический вопрос без ответа |
| A2 | Формат строгий, но пункт остаётся неблокирующим: сообщается вместе с ревью кода, заметка обязательна |

## Изменения по файлам

### `references/checklist.md`

**A2 — переписать.** Формат ровно `WEB-NN Фамилия Имя`: группа первой,
капсом, имя на русском, больше ничего. Недопустимы «Вариант N», «ДЗ0», «HW0»,
латиница, группа в конце. Заметка обязательна и называет целевое название
целиком. Убрать фразу «точный порядок слов и пунктуация не принципиальны» и
пример «Фамилия Имя, WEB-22» как допустимый. Причина в тексте: старший ментор
возвращает PR только за это.

**A4 — дополнить.** Если тронут `README.md` ветки варианта — откат только
через git (`git checkout origin/variant-N -- README.md` и новый коммит), не
вставкой текста обратно: после вставки git всё равно видит изменение.

**B1 — расширить.** Три подпункта:

1. *Реакция на невалидный вход.* По умолчанию `throw new TypeError`. Возврат
   `null`/`{}`/`[]` — вопрос «почему не ошибка?». Если поведение описано в
   JSDoc и одинаково для всех невалидных входов, находкой не считается.
2. *Элементы коллекции и ключ.* Проверка одного верхнего типа недостаточна:
   массив строк — что элементы строки; массив объектов — что элементы объекты;
   ключ — что непустая строка и что делать, когда ключа нет у части элементов.
3. *Экзотические объекты.* `Date`, `Map`, `Set`, `new String()`, `new Number()`
   проходят `typeof x === 'object'` и `!Array.isArray(x)`, но plain-объектами
   не являются. Универсальная проверка —
   `Object.prototype.toString.call(x) === '[object Object]'`; цепочка
   `instanceof` — перебор, который не закрыть. Обратная сторона для вариантов
   со строкой на входе (13, 14, 15, 19): `new String('abc')` — валидная строка,
   `typeof !== 'string'` её отбрасывает зря.

**B8 — усилить.** `for...of` по массиву с внешним аккумулятором — находка, а
не nit: старший ментор возвращает за это после аппрува ментора. Исключение —
перебор ключей объекта, если он не выражается через `Object.entries`.
Существующий абзац про захваченный аккумулятор и `forEach` не меняется.

**B11 — дополнить** списком микропаттернов:

- тернарник вместо `if/else`, в обеих ветках которого `return` или
  присваивание одной переменной;
- `const x = cond ? a : b` вместо `let x; if (...) x = a; else x = b`;
- деструктурирующий свап `[arr[i], arr[j]] = [arr[j], arr[i]]`;
- одно и то же условие дважды (или условие и его отрицание) — вынести в
  функцию-предикат с JSDoc в том же файле;
- `!array.length` вместо `array.length === 0`;
- `result[key] = [item]` вместо `result[key] = []; result[key].push(item)`;
- `const result = []` с `push(...items)` или spread вместо `let` с `concat`;
- одна копия входного массива, не две (внешняя функция и внутренняя
  сортировка копируют обе);
- `const { result } = reduce(...)` вместо промежуточной переменной `state`.

**B12 — новый пункт «Вопросы сверх задания».** Задаются в первом ревью как
вопросы на понимание, не как замечания. Переделка и аргументированный отказ
одинаково закрывают тред; при повторном ревью ответ без переделки — статус
«исправлено».

| Где | Вопрос |
|---|---|
| Подсчёт частот в объект (9, 13, 17) | Почему объект, а не `Map`? |
| Поиск максимума циклом (13) | `Math.max` и методы массива дают тот же ответ? |
| Функция с повторными вызовами и одинаковыми вычислениями (4) | Как не считать одно и то же дважды? |

**C0 — три новые строки** в таблице:

| Кейс | Для каких вариантов |
|---|---|
| Элементы коллекции не того типа (примитивы вместо объектов, числа вместо строк) | все с массивом на входе |
| Ключ пустая строка / ключа нет у части элементов | 6, 9, 10 |
| Экзотический объект (`Date`, `Map`, `Set`, `new String`, `new Number`) | 2, 3, 5, 6, 7, 8, 14, 18 |

Правило прежнее: строка в колонке «Нет» — обязательная заметка по C1.

**C3 — дополнить.** Сообщение ассерта описывает именно этот кейс.
«Сортирует по возрастанию, если все элементы уникальны» над массивом с
дублями — находка.

### `references/variants.md`

- **variant-4.** Старший ментор просит кэш: массив на уровне модуля, индекс
  равен `n`, значение — факториал; если `n` меньше длины — вернуть по индексу,
  иначе досчитать от последнего элемента, дописывая в массив. Без IIFE, без
  очистки кэша, с JSDoc на кэш. `if (cache[n])` достаточно — факториал
  положительный. Отдельный вопрос: откуда взялась граница `170`.
- **variant-15.** Деление на ноль: JS сам даёт `Infinity` и `-Infinity`,
  ручная подмена на `NaN` или `Infinity` — находка (вторая теряет знак).
  В тестах — кейс деления на ноль с обоими знаками.
- **variant-9, 13, 17.** Пункт про `Map` против объекта; 13 — ещё `Math.max`.
- **variant-6, 9, 10.** Ключ пустой; ключа нет у части элементов; элементы не
  объекты.
- **variant-1, 19.** Элементы массива не строки.
- **variant-2, 3, 5, 6, 7, 8, 14, 18.** Строка «экзотический объект на входе»
  со ссылкой на B1.
- **variant-13, 14, 15, 19.** Пометка про `new String()` как валидную строку.
- **variant-8.** Дополнить: вынести рекурсивную функцию за пределы `plainify`,
  чтобы она возвращала свой кусок, а не писала в захваченный аккумулятор.

### `references/comment-bank.md`

Формулировки для каждого нового пункта: A2 (строгий формат с примером
целевого названия), A4 (откат README через git), B1 (три подпункта, включая
подсказку «посмотри, что возвращает `Object.prototype.toString.call()` для
разных объектов»), B8 (`for...of` с аккумулятором), B11 (по одной фразе на
микропаттерн), B12 (три вопроса), C0/C1 (элементы, ключ, экзотика), C3
(сообщение ассерта), variant-4 (кэш, «как получил 170»), variant-15
(`±Infinity`). Где формулировка старшего ментора хороша — берётся его
интонация, не дословно.

### `SKILL.md`

Фаза 2, повторное ревью: статус «студент ответил вопросом» дополняется
статусом «вопрос без ответа» — тред ментора с теоретическим вопросом, на
который студент не ответил и код не менял.

Фаза 3, пункт «Предлагаемый вердикт»: пока есть хоть один тред со статусом
«вопрос без ответа», вердикт — `COMMENT`, лейбл «Нужны исправления», а в
сводке — напоминание, на какие вопросы ждём ответ. «ОК от ментора» не
предлагается.
