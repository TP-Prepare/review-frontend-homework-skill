# Упаковка скилла в плагин Claude Code — дизайн

**Дата:** 2026-09-07
**Статус:** утверждён

## Задача

Сейчас скилл ставится клонированием репозитория в папку скиллов:

```bash
git clone https://github.com/TP-Prepare/review-frontend-homework-skill.git \
  ~/.claude/skills/review-homework
```

Это работает, но у способа три недостатка: нет версий, обновление руками через
`git pull`, и пользователь обязан знать про путь `~/.claude/skills/`.

Штатный канал распространения в Claude Code — **плагин, установленный из
маркетплейса**. Тогда установка выглядит так:

```
/plugin marketplace add TP-Prepare/review-frontend-homework-skill
/plugin install review-homework@tp-prepare
```

Claude Code сам выкачивает репозиторий, кладёт его в
`~/.claude/plugins/cache/<маркетплейс>/<плагин>/<версия>/`, записывает версию и
SHA коммита в `installed_plugins.json` и умеет обновлять.

## Как это устроено на самом деле

Проверено на установленном локально плагине `superpowers` 6.3.0 и на
официальном маркетплейсе `anthropics/claude-plugins-official`.

**Плагин** — это git-репозиторий с `.claude-plugin/plugin.json`. Скиллы внутри
него лежат в `skills/<имя>/SKILL.md`. Минимальный манифест из
first-party плагина `code-review`:

```json
{
  "name": "code-review",
  "description": "Automated code review for pull requests…",
  "author": { "name": "Anthropic", "email": "support@anthropic.com" }
}
```

**Маркетплейс** — git-репозиторий с `.claude-plugin/marketplace.json`, где
перечислены плагины. Схема: `https://anthropic.com/claude-code/marketplace.schema.json`.

Репозиторий может быть **одновременно маркетплейсом и плагином** — так сделан
`superpowers`: в его `marketplace.json` единственный плагин с `"source": "./"`.
Этот приём мы и повторяем: одна репа, одна команда добавления, один плагин.

**Модерации нет.** Добавление своего маркетплейса — это выкачивание твоей репы
и чтение манифеста, никакого реестра или апрува посередине. Всё начинает
работать в тот момент, когда манифесты попадают в репозиторий, а он становится
доступен пользователю. Официальный маркетплейс `anthropics/claude-plugins-official`
— отдельная история: туда попадают через PR, и внешние плагины там пришпилены к
конкретному SHA. Нам он не нужен: аудитория скилла — менторы одного курса.

## Что меняется

### Раскладка

Claude Code ищет скиллы плагина в `skills/`. Сейчас скилл лежит в корне репы,
поэтому файлы переезжают:

```
до                          после
SKILL.md                 →  skills/review-homework/SKILL.md
references/*.md          →  skills/review-homework/references/*.md
                            .claude-plugin/plugin.json        (новый)
                            .claude-plugin/marketplace.json   (новый)
                            LICENSE                           (новый)
README.md                →  README.md            (остаётся, меняется установка)
docs/specs/*.md          →  docs/specs/*.md      (остаются)
docs/plans/*.md          →  docs/plans/*.md      (остаются)
```

Доки уже разложены по назначению: `docs/specs/` и `docs/plans/`, парами с
общим именем — `specs/review-homework.md` описывает то, что реализует
`plans/review-homework.md`. Эта работа ничего в них не двигает, только правит
устаревшие после переезда скилла места.

### Установка ломается и заменяется

Однострочник `git clone <url> ~/.claude/skills/review-homework` после переезда
работать перестаёт: он положит скилл на два уровня глубже, чем нужно. Это
осознанная плата за плагин. README переписывается на `/plugin install`, а для
тех, кому нужна установка без плагина, добавляется запасной вариант:

```bash
git clone https://github.com/TP-Prepare/review-frontend-homework-skill.git /tmp/rh \
  && cp -r /tmp/rh/skills/review-homework ~/.claude/skills/
```

### Устаревающие ссылки

Переезд делает неверными три места, и все три надо поправить в том же заходе:

1. `README.md` — раздел «Установка» и таблица «Структура» с путями `references/…`
2. `docs/specs/review-homework.md` — дерево архитектуры и фраза про то, что скилл занимает
   корень репозитория
3. `docs/plans/review-homework.md` — историческая справка прямо утверждает
   «здесь скилл лежит в корне, без каталога `review-homework/`», что после
   переезда становится ложью

## Решения

| Вопрос | Решение |
|---|---|
| Имя маркетплейса | `tp-prepare` — по владельцу репозитория |
| Имя плагина | `review-homework` — совпадает с именем скилла |
| Стартовая версия | `1.0.0` |
| Лицензия | MIT — **требует подтверждения владельца** |
| Официальный маркетплейс | не подаём, аудитория узкая |
| Публикация репы | **вне объёма**, см. ниже |

## Границы

**Перевод репозитория из private в public не входит в объём этой работы.**
Действие необратимо по смыслу — опубликованный код попадает в поисковые
индексы и форки, и откатить это нельзя. Решение принимает владелец
репозитория руками. Пока репа приватная, установка плагина работает только у
тех, у кого есть к ней доступ, — этого достаточно, чтобы всё проверить.

Также не входит: подача в `anthropics/claude-plugins-official`, публикация в
npm (не канал для скиллов Claude Code), CI и автотесты.

## Как проверяется

Автотестов у репозитория нет, деливерабл — документация и манифесты. Проверки
структурные:

1. Оба JSON-манифеста парсятся
2. `skills/review-homework/SKILL.md` существует и открывается корректным
   YAML-фронтматтером с `name: review-homework`
3. Контракты скилла целы: 22 идентификатора чек-листа совпадают с секциями
   банка формулировок, 19 вариантов, ноль пишущих команд в секции «Сбор»
4. Ни в одном файле не осталось ссылок на старые пути
5. На свежем клоне репозитория пути из `marketplace.json` разрешаются: от
   корня, куда указывает `"source": "./"`, виден `skills/review-homework/SKILL.md`
