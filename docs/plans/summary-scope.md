# Сводка не распределяет работу — план реализации

> **Для агентных исполнителей:** ОБЯЗАТЕЛЬНЫЙ САБ-СКИЛЛ: используйте
> superpowers:subagent-driven-development (рекомендуется) или
> superpowers:executing-plans, чтобы выполнять план задача за задачей.
> Шаги отмечаются чекбоксами (`- [ ]`).

**Цель:** запретить сводному комментарию пересказывать инлайн-заметки и
распределять работу между ними — на живом PR такая фраза стоила студенту суток.

**Архитектура:** правки только в текстах скилла. Новое железное правило 7 в
`SKILL.md` рядом с правилом 6, явный состав сводки в пункте 7 Фазы 3, пометка
про объём в банке формулировок, версия в манифесте.

**Технологии:** Markdown.

**Спека:** [`docs/specs/summary-scope.md`](../specs/summary-scope.md)

## Глобальные ограничения

- Тексты на русском, обращение к студенту на «ты».
- Правило 6 не трогается: оно про инлайн-заметки. Новое правило на него
  ссылается.
- Шаблоны в `comment-bank.md` не переписываются — они верны, им просто не
  следовали. Добавляется только пометка рядом.
- Числовой лимит длины сводки не вводится ни в каком виде.
- Уже опубликованные сводки на живых PR задним числом не правятся.
- Многострочную прозу править `Edit`, а не `sed`: на этой спеке `sed` уже
  склеил остаток старой строки с новой.

### Задача 1: правило 7 и состав сводки в `SKILL.md`

**Файлы:**
- Изменить: `skills/review-homework/SKILL.md`, секция «Железные правила»
- Изменить: `skills/review-homework/SKILL.md`, Фаза 3, пункт 7

**Интерфейсы:**
- Отдаёт: правило 7, на которое ссылаются пункт 7 Фазы 3 (эта же задача) и
  пометка в банке (задача 2).

- [ ] **Шаг 1: добавить правило 7**

Правило 6 сейчас заканчивается словами «…— полноценная заметка, её оставляем
инлайном.» и дальше идёт заголовок `## Фаза 0 — Старт`. Вставить между ними:

```markdown
7. **Сводка не распределяет работу.** Каждая инлайн-заметка уже несёт свою
   просьбу (правило 6), поэтому сводному комментарию незачем их пересказывать
   и тем более сортировать на «это правь, а это ответь». Сортировка, написанная
   в сводке, читается как итог всего ревью и перекрывает сами заметки: на живом
   PR фраза «переделывать ничего не нужно», сказанная про три вопроса на
   понимание из одиннадцати заметок, была прочитана как «переделывать не нужно
   вообще» — студент потерял день и пошёл выяснять в личку. В сводку идёт только
   то, чему негде жить инлайном: знакомство, похвала, просьбы вне диффа
   (переименовать PR), закрывающая строка и — если среди заметок есть заметно
   более важная — одна фраза про неё. Всё остальное живёт в тредах.
```

- [ ] **Шаг 2: дополнить пункт 7 Фазы 3**

Заменить целиком:

```markdown
7. **Сводный комментарий** — то, что уйдёт в тело ревью. Сюда же собирается
   похвала за то, что студент сделал хорошо. **В первом ревью открывается
   знакомством** с именем ментора и контактом из Фазы 0 — формулировка в
   `references/comment-bank.md`, секция «Сводный комментарий». При повторном
   ревью знакомство не повторяется, а в закрывающей строке контакт не
   дублируется
```

на:

```markdown
7. **Сводный комментарий** — то, что уйдёт в тело ревью. Состав закрыт
   правилом 7. Входит: знакомство, похвала за то, что студент сделал хорошо,
   просьбы вне диффа (например, переименовать PR), закрывающая строка и — если
   среди заметок есть заметно более важная — одна фраза про неё. Не входит:
   пересказ инлайн-заметок и любое распределение «это правь, а это ответь» —
   каждая заметка уже сказала это сама. **В первом ревью открывается
   знакомством** с именем ментора и контактом из Фазы 0 — формулировка в
   `references/comment-bank.md`, секция «Сводный комментарий». При повторном
   ревью знакомство не повторяется, а в закрывающей строке контакт не
   дублируется
```

- [ ] **Шаг 3: проверить результат**

```bash
grep -c '^7\. \*\*Сводка не распределяет работу' skills/review-homework/SKILL.md
sed -n '/^## Железные правила/,/^## Фаза 0/p' skills/review-homework/SKILL.md | grep -c '^[0-9]\+\. \*\*'
grep -c 'Состав закрыт' skills/review-homework/SKILL.md
grep -c 'Чистая похвала треда не оправдывает' skills/review-homework/SKILL.md
grep -c 'Сюда же собирается' skills/review-homework/SKILL.md
```

Ожидается `1`, `7`, `1`, `1`, `0`.

Пояснение к якорям, они выбраны не наугад:

- второй греп считает правила **внутри секции**, а не по всему файлу: в
  `SKILL.md` нумерованные строки с жирным есть ещё в Фазе 3 и Фазе 4, и греп по
  всему файлу даёт 16, а не число правил;
- четвёртый греп проверяет, что правило 6 цело, и берёт однострочный кусок его
  текста: фраза «Каждый инлайн-комментарий в GitHub заводит тред» разорвана
  переводом строки, а греп построчный и её не найдёт;
- пятый греп должен дать `0`: «Сюда же собирается» — обрывок старой редакции
  пункта 7 Фазы 3, после замены его быть не должно.

- [ ] **Шаг 4: коммит**

```bash
git add skills/review-homework/SKILL.md
git commit -m "feat(skill): правило 7 — сводка не распределяет работу"
```

### Задача 2: пометка про объём в банке формулировок

**Файлы:**
- Изменить: `skills/review-homework/references/comment-bank.md`, секция
  «Сводный комментарий»

**Интерфейсы:**
- Потребляет: правило 7 из задачи 1 — пометка на него ссылается.

- [ ] **Шаг 1: добавить пометку перед шаблоном первого ревью**

В секции «Сводный комментарий» сейчас идёт блок про знакомство, затем строка
«Первое ревью, есть замечания. При знакомстве — без своего «Привет!»,
начинается со второй фразы: знакомство уже поздоровалось.» и сам шаблон.

Вставить пометку **перед** строкой «Первое ревью, есть замечания…»:

```markdown
**Шаблоны задают не только тон, но и объём.** Если сводка выросла настолько,
что пересказывает инлайн-заметки, её надо урезать до состава из правила 7 в
`SKILL.md`: знакомство, похвала, просьбы вне диффа, закрывающая строка и, если
есть заметно более важная заметка, одна фраза про неё. На живых прогонах сводки
доходили до 219–348 слов при шаблоне в 30 — и именно в этом пересказе родилась
фраза, которую студент прочитал как «переделывать ничего не нужно».
```

- [ ] **Шаг 2: проверить результат**

```bash
grep -c 'Шаблоны задают не только тон' skills/review-homework/references/comment-bank.md
grep -c 'правила 7' skills/review-homework/references/comment-bank.md
grep -c 'Привет! Посмотрел твоё решение — в целом направление верное' skills/review-homework/references/comment-bank.md
```

Ожидается `1`, `1`, `1`. Третий греп подтверждает, что сам шаблон первого
ревью не изменён.

- [ ] **Шаг 3: коммит**

```bash
git add skills/review-homework/references/comment-bank.md
git commit -m "feat(comment-bank): пометка про объём сводки"
```
