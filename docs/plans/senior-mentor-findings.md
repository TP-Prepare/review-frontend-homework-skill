# Правки старшего ментора в чек-листе — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Заложить в скилл `review-homework` девять повторяющихся тем старшего ментора, чтобы черновик ловил их до передачи PR на финальную проверку.

**Architecture:** Только справочники и процесс: четыре markdown-файла скилла получают новые пункты, ни один существующий пункт не удаляется, кроме противоречащего A2. Каждая задача — один файл, проверяется `grep`-ом на присутствие новых формулировок и отсутствие старых. Последняя задача — версия плагина и сухой прогон скилла на живом PR без постинга.

**Tech Stack:** Markdown (Claude Code skill format), `gh` CLI, `git`.

**Spec:** [`../specs/senior-mentor-findings.md`](../specs/senior-mentor-findings.md)

```markdown
Самая частая содержательная претензия, и у неё три уровня.

**B1.1. Реакция на невалидный вход.** По умолчанию — `throw new TypeError`
с понятным сообщением. Возврат `null`, `{}` или `[]` вместо ошибки получает
вопрос «почему не ошибка?». Если такое поведение описано в JSDoc и одинаково
для всех невалидных входов (а не `null` в одном месте и `{}` в другом), это
осознанный выбор, а не находка: старший ментор такой ответ принимает.

**B1.2. Элементы коллекции и ключ.** Проверки одного верхнего типа мало.
Массив строк — что каждый элемент строка; массив объектов — что каждый
элемент объект, а не примитив; ключ — что это непустая строка, и что делает
функция, когда ключа нет у части элементов (`obj[key] === undefined`). Каждый
из этих случаев — отдельная строка в C0.

**B1.3. Экзотические объекты.** `Date`, `Map`, `Set`, `new String('a')`,
`new Number(1)` проходят и `typeof x === 'object'`, и `!Array.isArray(x)`,
и `x !== null`, но plain-объектами не являются: `Object.entries` от них даёт
пустой массив или индексы символов. Универсальная проверка —
`Object.prototype.toString.call(x) === '[object Object]'`; цепочка
`instanceof Date && instanceof Map && …` — перебор, который не закрыть,
потому что классов больше, чем перечислишь. Подсказку даём вопросом: «посмотри,
что возвращает `Object.prototype.toString.call()` для разных объектов».

Обратная сторона для вариантов со строкой на входе (13, 14, 15, 19):
`new String('abc')` — валидная строка, а `typeof x !== 'string'` её
отбрасывает. Тот же `toString.call` даёт `[object String]` для обеих форм.
```
