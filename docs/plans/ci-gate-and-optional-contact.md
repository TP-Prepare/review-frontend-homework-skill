# Гейт CI и контакт по желанию — план реализации

> **Для агентных исполнителей:** ОБЯЗАТЕЛЬНЫЙ САБ-СКИЛЛ: используйте
> superpowers:subagent-driven-development (рекомендуется) или
> superpowers:executing-plans, чтобы выполнять план задача за задачей.
> Шаги отмечаются чекбоксами (`- [ ]`).

**Цель:** научить скилл самому снимать гейт `action_required` вместо того чтобы
просить об этом не того человека, и дать ментору право отказаться от внешнего
контакта в знакомстве.

**Архитектура:** правки только в текстах скилла. Правило 1 получает третье
исключение, Фаза 1 — шаг про гейт, Фаза 0 — формулировку про отказ от контакта,
`gh-recipes.md` — рабочий рецепт вместо неверной фразы, банк — второй шаблон
знакомства.

**Технологии:** Markdown, `gh` CLI.

**Спека:** [`docs/specs/ci-gate-and-optional-contact.md`](../specs/ci-gate-and-optional-contact.md)

## Глобальные ограничения

- Тексты на русском, обращение к студенту на «ты».
- Правила 2–6 не трогаются. Правило 7 меняется ровно в одном месте — второй
  пример третьего слота.
- Формулировки третьего слота в правиле 7 и в пункте 7 Фазы 3 обязаны совпадать
  дословно — это требование прошлого батча.
- Фазы 2, 2.5 и 4, `checklist.md`, `variants.md` не трогаются.
- Многострочную прозу править `Edit`, а не `sed`.
- Якоря проверок однострочные. Если якорь окажется разорван переводом строки —
  не переформатируй текст под греп: возьми ближайший однострочный кусок и скажи,
  какой и почему.

### Задача 2: рецепт одобрения в `gh-recipes.md`

**Файлы:**
- Изменить: `skills/review-homework/references/gh-recipes.md`, секция «Статус CI»

**Интерфейсы:**
- Потребляет: правило 1 и шаг Фазы 1 из задачи 1 — рецепт на них ссылается.

- [ ] **Шаг 1: заменить абзац про `action_required`**

Заменить целиком:

```markdown
`conclusion: action_required` (длительность `0s`) — это гейт GitHub для
первого контрибьютора с форка: запуск создан, но ждёт одобрения мейнтейнера
во вкладке Actions репозитория. Это не вина студента. Просьба одобрить запуск
во вкладке Actions — это просьба к студенту и она вне диффа, ей место в сводке
в слоте «просьбы вне диффа» из правила 7. А агенту в Фазе 2 из-за этого нужно
просмотреть `eslint` и тесты глазами внимательнее — раз автопроверки не
прогонялись, в сводку это указание не идёт.
```

на:

````markdown
`conclusion: action_required` (длительность `0s`) — это гейт GitHub для
контрибьютора с форка: запуск создан, но ждёт одобрения. Снять его может только
тот, у кого есть `push` к репозиторию потока; студент со своего форка не может,
просить его бессмысленно. Скилл одобряет сам — правило 1 это разрешает:

```bash
gh api "repos/$R/actions/runs/<databaseId>/approve" --method POST
gh run watch <databaseId> -R $R --exit-status
```

`databaseId` — из `gh run list` выше. После `gh run watch` статус читается
заново, и в черновик идёт он, а не «ждёт одобрения».

Если прав не хватает:

```bash
gh api "repos/$R" -q .permissions.push
```

`false` — одобрить может только ментор. Тогда это идёт **в шапку черновика**, а
не в сводку: студент тут ни при чём и сделать ничего не может. И тогда же
`eslint` с тестами просматриваются глазами внимательнее — автопроверки не
прогонялись, полагаться не на что.
````

- [ ] **Шаг 2: проверить результат**

```bash

grep -c 'actions/runs' skills/review-homework/references/gh-recipes.md
grep -c 'permissions.push' skills/review-homework/references/gh-recipes.md
grep -c 'gh run watch' skills/review-homework/references/gh-recipes.md
```

Ожидается `0`, `1`, `1`, `1`.
