# Варианты задания

19 вариантов, `variant-1` … `variant-19`. Файлы: `source/<функция>.js` и
`test/<функция>.js`. Читать только секцию нужного варианта.

Общее для всех: `'use strict'` первой строкой, JSDoc на каждую функцию,
проверка входных данных, включая элементы коллекции (B1.2), пустая строка в
конце файла, `const`, стрелочная функция (кроме `variant-16`).

## Как читать «На что посмотреть»

Пункт в этом списке — **повод задать вопрос, а не диагноз**. Он говорит, где
менторы прошлых потоков находили проблемы, а не что решение студента заведомо
плохое. Прежде чем требовать замену:

1. **Проверь, не закрывает ли текущее решение другой пункт из этой же секции.**
   Пункты внутри одной секции нередко описывают два конца одного компромисса.
   У `variant-8` раньше это были «рекурсивная функция объявлена внутри
   `plainify`» и «служебные параметры рекурсии торчат наружу в сигнатуре»:
   убрал замыкание — получил второй пункт. Сейчас секция варианта показывает
   выход, который закрывает оба: помощник на уровне модуля возвращает свой
   кусок, а публичная сигнатура `plainify` остаётся чистой. Если такого выхода
   в секции нет — требовать оба пункта сразу нельзя, а требование одного
   вслепую делает решение хуже.
2. **Прогони код (Фаза 2.5), прежде чем называть это проблемой.** Часть пунктов
   — про производительность и про поведение на краях; и то и другое проверяется
   запуском, а не чтением.
3. **Если решение осознанное и задокументировано в JSDoc — это не находка.**
   Спроси, что студент за это платит и что покупает, и оставь выбор за ним.
4. **Циклические ссылки не поднимаем ни в одном варианте.** Ни одно задание
   их не требует, а защита стоит дорого — в `deepClone` она ломает и
   `value.map(deepClone)`, и `Object.fromEntries`, потому что копию надо
   класть в `WeakMap` до спуска в детей, а сам `WeakMap` тащить служебным
   параметром в публичную сигнатуру. Размен читаемого решения на это ради
   `RangeError` вне условия — не то, чему мы учим на ДЗ0.

## variant-1 — fetchAndMerge

Принимает массив URL, загружает данные, возвращает объект со всеми уникальными
ключами. Повторяющийся ключ → массив уникальных значений.

На что посмотреть: последовательные `await` в цикле вместо `Promise.all`;
не обработаны сетевые ошибки и не-200 ответы; в JSDoc забыт `@async` и то, что
возвращается промис; дубли значений не отсеиваются; элементы массива не
проверены на то, что это строки (B1.2).

Тесты: мок `fetch`, пустой массив URL, ошибка сети, одинаковые ключи в разных
ответах, невалидный URL, массив не из строк.

## variant-2 — deepMerge

Два объекта → один. Одинаковые ключи с объектами сливаются рекурсивно, иначе
значение из второго перезаписывает первое.

На что посмотреть: **мутация входных объектов** — самая частая ошибка варианта;
вложенные объекты протекают по ссылке (`result.user.name = 'Bob'` меняет
`source`); `typeof null === 'object'` ломает рекурсию; массивы — по условию не
сливаются рекурсивно, но это стоит отразить в JSDoc.

Экзотический объект на входе (`Date`, `Map`, `Set`) проходит `typeof` и
`!Array.isArray` — см. B1.3.

Тесты: приоритет второго объекта при конфликте, глубокая вложенность, `null` в
значениях, исходники не изменились после вызова, `Date` или `Map` вместо
объекта.

## variant-3 — compressObject

Возвращает новый объект без ключей со значениями `null`, `undefined` и пустой
строки.

На что посмотреть: проверка через `if (!value)` вместо трёх конкретных значений —
**`0` и `false` тоже отсеются, а не должны**; мутация исходного объекта.

`new String('a')`, `new Number(1)`, `Date`, `Map`, `Set` проходят guard
`typeof obj === 'object' && obj !== null && !Array.isArray(obj)` — см. B1.3.
Старший ментор просит `Object.prototype.toString.call`.

Тесты: значения `0` и `false` сохраняются, все три отсеиваемых значения,
пустой объект, вложенные объекты, экзотический объект на входе.

## variant-4 — factorial

Неотрицательное целое `n` → факториал.

На что посмотреть: нет проверки на отрицательное, дробное и не-число; `0! = 1`
забыт; рекурсия без ограничения глубины; потеря точности на больших `n`.

**Кэш — спросит старший ментор (B12).** Повторный вызов пересчитывает те же
умножения. Форма, которую он принимает: массив на уровне модуля, индекс равен
`n`, значение — факториал; если `n` меньше длины массива — вернуть по индексу,
иначе досчитать от последнего элемента, дописывая в массив. Чего он не
принимает: IIFE-обёртка вокруг функции, очистка кэша по размеру («массив из
50 элементов — не та память, ради которой стоит пересчитывать»), поиск
ближайшего посчитанного с делением. К кэшу нужен JSDoc. `if (cache[n])`
достаточно — факториал положительный, `0` и `undefined` там не лежат.

Если студент ограничил `n` числом вроде `170` (после него `Infinity`) — спросить,
откуда взялась граница. Это вопрос на понимание, не замечание.

Тесты: `0`, `1`, отрицательное (выброс ошибки), дробное, строка, `null`,
большое значение, два вызова подряд дают один результат (если есть кэш).

## variant-5 — deepClone

Глубокая копия объекта.

На что посмотреть: `Date`, `Map`, `Set`, `RegExp` копируются неправильно —
превращаются в `{}`, потому что `Object.entries` от них даёт пустой массив;
массивы превращаются в объекты; `typeof null === 'object'`; объект без
прототипа (`Object.create(null)`) теряет прототип. `new String('abc')` и
`new Number(123)` — тот же класс проблемы, старший ментор просит тесты на них
отдельно (B1.3).

Тесты: вложенность, массивы, `Date`, `null`, `new String`, `new Number`,
объект без прототипа, изменение копии не трогает оригинал.

**Циклические ссылки в этом варианте не поднимаем** — см. правило выше.

## variant-6 — filterByKeys

Объект и массив ключей → новый объект только с этими ключами. Отсутствующий
ключ игнорируется.

На что посмотреть: значения-объекты копируются по ссылке — по условию их нельзя
изменять; не проверено, что `keys` вообще массив; `hasOwnProperty` против
унаследованных свойств. Ключ в `keys` пустая строка или не строка;
экзотический объект вместо `obj` (B1.2, B1.3).

Тесты: ключа нет в объекте, пустой массив ключей, `null` вместо объекта,
вложенный объект не мутируется, пустая строка среди ключей, `Date` вместо
объекта.

## variant-7 — transform

Объект и функция преобразования. Функция применяется к каждому значению,
вложенные объекты обрабатываются рекурсивно.

На что посмотреть: мутация исходного объекта; не проверено, что `transformFn` —
функция; массивы внутри объекта. Экзотический объект на входе или в значениях
— B1.3.

Тесты: вложенность, `transformFn` не функция, пустой объект, исходник не
изменился, `Map` вместо объекта.

## variant-8 — plainify

Объект с вложенными свойствами → plain-объект.

На что посмотреть: **рекурсивная функция объявлена внутри `plainify`**,
пересоздаётся при каждом вызове и пишет в захваченный аккумулятор `result` —
старший ментор просит вынести её наружу так, чтобы она возвращала свой кусок,
а `plainify` собирал результат (`Object.assign` в аккумулятор на уровне
вызова, не spread — см. B8); служебные параметры рекурсии торчат наружу в
сигнатуре; формат составного ключа не задокументирован;
возврат `null` на невалидный вход вместо `TypeError` (B1.1); экзотический
объект на входе (B1.3).

Тесты: глубокая вложенность, пустой объект, массивы, `null`,
`Date`/`Map`/`new String` на входе.

## variant-9 — groupBy

Массив объектов и ключ → объект, где ключи это уникальные значения поля.

На что посмотреть: цикл вместо `reduce`; объекты без нужного ключа не обработаны;
не проверено, что первый аргумент массив, а второй строка. Элементы массива
не объекты; ключ пустая строка; ключа нет у части элементов — что попадает в
результат (B1.2). Частоты или группы в plain-объект — вопрос про `Map` (B12).

Тесты: ключа нет в части объектов, пустой массив, одинаковые значения ключа,
невалидные аргументы, массив примитивов, пустой ключ.

## variant-10 — mergeBy

Два массива объектов и ключ. Объекты с одинаковым значением ключа сливаются,
массивы-свойства объединяются без дубликатов.

На что посмотреть: `includes` внутри цикла даёт **O(n²)** — лучше `Set`;
мутация входных массивов; объекты, у которых ключа нет. `obj[key] === undefined`
не должен ломать слияние (B1.2). Ключ пустая строка — тоже B1.2. `for...of` с
накоплением в `Map`/массив — `reduce` (B8).

Тесты: объекты с одинаковым ключом внутри одного массива, слияние
массивов-свойств с дубликатами, пустые массивы, объект без ключа в одном из
массивов.

## variant-11 — partition

Массив и предикат → массив из двух массивов.

На что посмотреть: два отдельных массива и `push` вместо `reduce`; не проверено,
что `predicate` функция; предикат вызывается дважды на элемент.

Тесты: все элементы проходят, ни один не проходит, пустой массив, предикат не
функция.

## variant-12 — flatten

Вложенный массив любой глубины → плоский.

На что посмотреть: нет проверки, что аргумент массив — падает на `null`;
рекурсия без ограничения; пустые вложенные массивы.

Тесты: глубокая вложенность, пустые вложенные массивы, элементы разных типов,
не-массив на входе, исходник не изменился.

## variant-13 — emailAnalyzer

Строка → `{ emailCount, uniqueEmails, mostFrequentEmail }`. Регистр
игнорируется.

На что посмотреть: **регулярка внутри функции** — надо вынести в константу
модуля; регистр не приводится к нижнему; `mostFrequentEmail` через цикл вместо
`reduce`; пустая строка и отсутствие адресов. Частоты в plain-объект — вопрос
про `Map`; максимум циклом по ключам — вопрос про `Math.max` и методы массива
(B12). `new String('…')` — валидный вход (B1.3).

Тесты: пустая строка, адресов нет, разный регистр одного адреса, одинаковая
частота у нескольких адресов (по условию допустим любой из них — не требуй от
студента детерминированного результата), не строка на входе.

## variant-14 — templateEngine

Шаблон и объект данных. `{{user.name}}` — вложенные переменные. Ненайденная
переменная → пустая строка.

На что посмотреть: регулярка не вынесена в константу; колбэк `replace` не
стрелочный; вложенный путь не разбирается; пробелы внутри `{{ ключ }}`;
значение `0` или `false` теряется из-за проверки на falsy. `new String('{{a}}')`
— валидный шаблон, `typeof !== 'string'` его отбрасывает; `Date`/`Map`/`Set`
вместо объекта данных — невалидны, старший ментор просит
`Object.prototype.toString.call` (B1.3).

Тесты: переменной нет в данных, вложенный путь, пустой шаблон, значение `0`,
не строка на входе, `Date` вместо объекта данных.

## variant-15 — polishNotationEvaluator

Строка в префиксной нотации → результат. Операторы `+`, `-`, `*`, `/`.

На что посмотреть: **деление на ноль подменено руками** — JS сам даёт
`Infinity` для `1 / 0` и `-Infinity` для `-1 / 0`, а `b === 0 ? NaN : a / b`
и `b === 0 ? Infinity : a / b` — находки, вторая ещё и теряет знак; невалидное
выражение не обрабатывается; унарный минус в операндах; лишние пробелы;
операторы не вынесены в константу; `new String('+ 1 2')` — валидный вход
(B1.3).

Тесты: все четыре оператора, вложенные выражения, деление на ноль с обоими
знаками (`+ 1 / 1 0` и `/ -1 0`), невалидное выражение, пустая строка,
отрицательные операнды, невалидные входы разных типов, не только число.

## variant-16 — fibonacciGenerator

Число `n` → генератор первых `n` чисел Фибоначчи. При `n <= 0` не выдаёт ничего.

На что посмотреть: **не требовать стрелочную функцию** — генератор объявляется
только через `function*`; возвращается массив вместо генератора; `n <= 0` не
обработано; JSDoc не отражает, что возвращается `Generator`.

Тесты: `n = 0`, отрицательное `n`, `n = 1`, первые несколько чисел, что
возвращается именно генератор (`typeof result.next === 'function'`),
не-число на входе.

## variant-17 — sortByFrequency

Массив чисел → отсортированный по частоте. При равной частоте — по возрастанию.

На что посмотреть: **`sort()` мутирует входной массив** — нужен `[...array].sort()`;
частоты считаются циклом вместо `reduce`; второй критерий сортировки забыт.
Частоты в plain-объект — вопрос про `Map` (B12): на числовых ключах объект
приводит ключ к строке, `Map` нет.

Тесты: одинаковая частота у разных чисел, пустой массив, все элементы
уникальны, исходный массив не изменился, отрицательные числа.

## variant-18 — findUniqueProperties

Два объекта → объект только с уникальными для каждого свойствами.

На что посмотреть: цикл вместо `Object.keys` + `filter`/`reduce`; не проверено,
что оба аргумента объекты; вложенные объекты. Экзотический объект вместо
одного из аргументов (B1.3).

Тесты: полностью совпадающие объекты, полностью разные, пустой объект, `null`
вместо объекта, `Set` вместо объекта.

## variant-19 — sortByLength

Массив строк → отсортированный по длине. При равной длине — по алфавиту.

На что посмотреть: **`sort()` мутирует входной массив** — нужен spread;
алфавитный порядок через `>` вместо `localeCompare`; не проверено, что элементы
строки. Это B1.2: массив чисел или смешанный массив — что возвращает функция.
`new String('a')` в элементах — валидная строка (B1.3).

Тесты: строки одинаковой длины, пустой массив, пустые строки, кириллица,
исходный массив не изменился, массив не из строк.
